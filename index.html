01 / Hardware

First, know what
you are renting.

A GPU does the model’s calculations. Its memory holds the model and the data it is working on. Servers supply power, storage, and connections; racks combine them into larger systems.

A faster chip helps only if the job fits and the rest of the system can keep it supplied.

02 / Networks

Chips work together.
Communication takes time.

In distributed training, GPUs calculate part of a result and exchange information before the next step. Some communication can happen alongside computation. The rest adds time to the step.

That is why a network constraint can leave expensive processors waiting.

03 / Economics

Commit to the work
you expect to use.

Reserved capacity costs money even when it sits idle. On-demand capacity can cost more per hour but lets you pay only when you need it.

The useful question is how often each additional GPU will be needed. Stable demand and occasional peaks call for different commitments.

04 / Contracts

A service promise needs
a measurement rule.

“99.9% uptime” leaves questions open. Is availability measured across the whole fleet or for each GPU? Which failures count? Is the remedy a refund, a credit, or the right to leave?

The same outage can produce different remedies under different definitions.
